# GUI 移植對照（PySide6 → egui）

文中的 `*.py` 指 Python 版的 `src/opendrs/gui/`（在 `main` 分支，或本分支的 commit `8aa7c0b`）。

Python 版 GUI（`src/opendrs/gui/*.py`，約 5,400 行）的功能清單，egui 版照這份做。中文字串一律與 Python 版逐字相同。
（2026-10-10 由程式碼整理；Python 版有改動時同步更新。）

## 0. 通則

- **歷史**：每次修改產生新的 `Project`，`commit(project, label)` → `History::push` → 重畫。表格儲存格編輯的標籤是 `編輯`；
  頻道移到別的分區是 `變更分區`。選單文字 `復原 {label}`／`重做 {label}`（去頭尾空白）。
- **表格編輯錯誤**：警告框「無法套用」＋訊息。設定區頁面的錯誤：警告後重畫（編輯器回到舊值）。
- **需要專案**：沒有任何資料時 `information(title, "請先開啟專案檔，或從對講機讀取。")`。
- **沒有右鍵選單**：所有列操作都在選單或按鍵上。

## 1. 主視窗

- 預設 1280×780。中央上下分割：上為分頁，下為群組框「問題清單」（有 N 項時 `問題清單（N）`）。
- 問題清單順序：
  1. `部分名稱無法以 {codec.label} 解碼（以 ‹十六進位› 顯示），請確認編碼`
  2. `{summary} 名稱含換行字元（顯示為 ␍␊），可按工具列「清除名稱中的換行字元」修正`
  3. `Project.problems()`
  沒有問題時顯示 `沒有問題`（勾號圖示）。
- 分頁（標題每次重畫更新）：`裝置資訊`、`頻道（N）`、`分區（N）`、`聯絡人（N）`、`掃描清單（使用中）`、`接收群組（使用中）`、
  `對講機設定`、`常用短信`、`報警與加密`。

### 標題、修改標記、開啟／關閉

- 標題 `{*}{name} — OpenDRS {version}`；name 是檔名，否則 `_source`，否則 `未開啟檔案`。
  `_source`：讀取後 `從對講機讀取（{model 或 ?}，尚未儲存）`；開啟備份後 `備份 {file}（存檔時另存新檔）`。
- 修改中：`project != saved`。讀取對講機後 saved 為空專案，所以一定是修改中。
- 捨棄前確認（開啟、最近開啟、拖放、讀取、開啟備份、關閉）：`尚未儲存`／`目前的修改尚未儲存，要先儲存嗎？`（儲存／不儲存／取消）。
- 傳輸中關閉：`傳輸中`／`與對講機的傳輸進行中，請等待完成。`，不關閉。
- 開啟：標題 `開啟專案`，從 `last_dir` 開始；失敗 `開啟失敗`／`{path}\n\n{exc}`；成功後重設歷史、清除篩選與排序、
  依名稱自動切換編碼（Rust 版用名稱欄位；Python 版傳整筆記錄，實際上從不切換）、加入最近開啟（最多 8 個）。
- 儲存：標題 `另存新檔`；失敗 `儲存失敗`。`f136::save` 在 `problems()` 非空時拒絕（`尚有問題未修正：…`），保留一次 `.bak`，原子寫入。
  儲存不更新最近開啟。
- 拖放：只接受一個本機檔案（任何副檔名）→ 確認捨棄 → 開啟。
- 進入點：`opendrs [檔案]`；啟動時搬移舊資料夾（訊息在狀態列顯示 20 秒）。

## 2. 頁面

### 2.1 裝置資訊

- 群組 `對講機`（空值顯示 `—`）：`機型`（`model（also）`，`hardware::known_as`）、`型號`、`韌體版本`、`版本日期`、`頻段標示`、
  `允許頻段`（`{lo:g}–{hi:g} MHz` 以 `、` 連接，或 `未知（不檢查）`）、`寫入時間`、`出廠編號`、`序號`。
- 群組 `本機身分`：
  - `別名`：最多 15 字元，提示 `最多 15 個英數字元`，說明 `最多 15 個英數字元；按 Enter 或離開欄位即套用`。
  - `本機 DMR ID`：1–16776415，提示 `1–16776415`。旁邊顯示 `未設定`／`尚未下載 RadioID 資料，無法查詢呼號`／`RadioID 查無 {id}`／
    `RadioID：{callsign} {first_name}（city、country）`，以及 `\n⚠ 別名 {alias} 與 RadioID 登記的呼號 {callsign} 不同（呼號可能已變更）`；
    按鈕 `以 RadioID 呼號更新別名`（呼號與別名不同時才顯示，比較時 casefold）。
  - 設定區太短時兩者停用。錯誤時還原文字並警告（標題為復原標籤）。復原標籤 `修改別名`、`修改 DMR ID`、`別名改為 RadioID 呼號`。
- 群組 `專案`：`設定區大小` = `{len:,} bytes（原樣保留）`。
- 註：`頻道記錄 +0x0C 為接收頻率、+0x10 為發射頻率（2026-10-08 以實機讀寫擷取確認）。`

### 2.4 掃描清單、接收群組

- 唯讀表格、單選；欄位 `#`、`名稱`、`數量`、`成員`；未使用的顯示灰色 `（未使用）`；成員以 `、` 連接；設定區沒有這一區時整頁停用；
  雙擊或按鈕 `編輯選取的清單…` 開編輯器。
- 掃描清單說明：`雙擊一列可編輯。清單最多 16 台頻道，依頻道清單順序掃描；刪除頻道或分區時，掃描清單會自動跟著調整。`
  項目文字 `{zone}／{channel}`、`{zone}／第 {c} 台（不存在）`、`分區 {z}／第 {c} 台（不存在）`。
- 接收群組說明：`雙擊一列可編輯。頻道的「接收群組」選擇這裡的清單；群組最多 32 個聯絡人。刪除聯絡人時，群組成員會自動移除並重新編號。`
- 成員編輯（480×600，標題 `掃描清單 {n}`／`接收群組 {n}`）：`名稱：`（提示 `名稱（最多 10 bytes）`）、`勾選要加入的{頻道|聯絡人}：`、
  篩選框 `篩選清單…`、勾選清單、`已勾選 {n} / {16|32} 個{單位}`（超過加 `　⚠ 超過上限` 並停用確定）；成員依清單順序存，不依勾選順序。
- 掃描另有：`回講：` Off/On、`掃描發射模式：` 當前信道／最後活動信道／指定信道、`指定信道：` Off＋項目（只在指定信道時啟用；未變更時保留舊值）。
- 復原 `編輯掃描清單 {n}`／`編輯接收群組 {n}`；錯誤標題 `掃描清單`／`接收群組`。

## 3. 對話框與背景工作

### 3.1 讀取／寫入／校正時鐘

- 連接埠選單：`{device} — {description}`，最後一項 `模擬對講機（試用）`；提示 `寫頻線連接埠`；重新整理提示 `重新列出連接埠（插拔寫頻線後使用）`；
  沒有埠 `找不到序列埠：請確認寫頻線已插入並安裝驅動程式`；列出失敗 `無法列出連接埠：{exc}`。選了或開始傳輸時存進設定。
- 傳輸中再按無作用；沒選埠 `請先在工具列選擇寫頻線的連接埠。`
- 讀取：先確認捨棄 → 背景讀取 → `save_backup(…,"read")` → 以未儲存專案載入；狀態列 15 秒 `已讀取 {summary}，備份：{path}`。
- 寫入（安全順序）：
  1. 需要專案；2. `check_writable` → 警告 `無法寫入`；3. 需選埠；
  4. 詢問 `寫入對講機`：`要寫入到 {port} 嗎？\n\n機型 …　…\n分區 …、頻道 …、聯絡人 …（N 個區塊）\n\n寫入前會先讀取對講機並備份到 {dir}；機型或頻段不符會中止。`
  5. 背景先讀取並備份為 `before_write`；6. `identity_mismatch` → `已中止，未寫入任何資料：{reason}`；
  7. 暫停 1.5 秒（模擬器 0）；8. 以現在時間寫入，交握時再檢查 `identity_mismatch`。
- 校正時鐘：確認 `校正對講機時鐘`（全文見 `radio_ops.py:113-118`）；讀取並備份 → `clock_write_project` 無法逐位元組重建就中止 → 身分檢查 → 暫停 → 寫入。
- 背景狀態：`{讀取|寫入|校正時鐘}：連線到 {port}…`、`寫入前先讀取對講機目前的設定並備份…`、`備份完成：{file}（{summary}）`、`開始寫入…`、
  `錯誤：{msg}`、`未預期的錯誤：{exc}`、`{mode}完成`；第一個區塊前進度條為忙碌狀態；不能取消。
- 結果：失敗 `對講機`＋錯誤或 `傳輸未完成。`；寫入成功訊息：`寫入完成，對講機確認校驗和 0x{:08X}。`、
  `對講機時鐘已設為 {date}（開始寫入時的電腦時間，秒數維持對講機原值）。`、`寫入前的設定已備份到：{path}`、`對講機正在套用設定，請等它重新啟動後再操作。`；
  校正時鐘成功見 `radio_ops.py:69-74`。

### 3.2 韌體升級（IAP）

- 表單（660×600）：`對講機目前韌體`、`連接埠`（空時 `未選擇（請在工具列選擇寫頻線）`）、`韌體檔`（唯讀路徑、`選擇…`、`產生錄音讀取版…`）、
  `檔案資訊`、`原廠 IAP 工具`（路徑＋`選擇…`）；下方 `檢查結果` 清單、兩個勾選框、步驟說明（`STEPS`）、進度條、狀態文字。
  勾選框：`我了解刷錯韌體可能使對講機無法開機`、`對講機已依原廠說明進入升級（IAP）模式，並以寫頻線連接到上面的連接埠`。
- 按鈕：關閉、`開始升級`、`停止`（執行中才顯示）、`改用原廠 IAP 工具`。
- 檢查：`firmware_check::check(檔案, 對講機韌體, 今天有備份, 對講機日期)`；傳輸中 BLOCK `本程式正在與對講機傳輸，請等完成後再升級`；
  內建升級沒選埠 BLOCK `內建升級：請先在主視窗工具列選擇寫頻線的連接埠`，否則 OK＋`VERIFIED`；原廠工具找不到 BLOCK `原廠工具：找不到 IAP+Flash.exe，請按「選擇…」指定`；
  沒選檔 `請先選擇韌體檔`。
- 硬體安全規則：
  - 檢查結果是空的也算 **BLOCK**（Rust 的 `verdict(&[])` 回傳 Ok，GUI 要自己處理）。
  - 有 WARN 時需勾第一個框；只有在有 WARN 且共同檢查沒有 BLOCK 時才能勾；換檔時清除。
  - `開始升級` 另需勾第二個框。
  - 開始時重新計算韌體檔 SHA-256；變了就 `韌體檔在檢查後被修改過，已重新檢查，請確認結果後再開始。`
  - 最後警告 `開始升級`：`即將清除對講機的韌體並寫入 {file}（{n} 頁）。\n開始後不可拔線或關機；若中途失敗，對講機會停在升級模式，可重新執行升級。\n\n要開始嗎？`（預設「否」）。
  - 執行中不能關閉：`升級進行中，請等完成或按「停止」。`；停止：`停止中（送完目前這一頁或停止等待回應）…`；每次執行後清除第二個框。
- 結果：成功 `升級完成：{pages} 頁，對講機確認校驗和 0x{:08X}（清除回覆：…）。…`；失敗 `升級未完成，`／`升級未開始，`（看清除指令是否已送出）＋訊息，或 `無法開啟連接埠：{exc}`。
- 錄音讀取修補：檔案狀態為 `patchable` 才顯示；存檔對話框 `儲存錄音讀取版韌體`，預設 `{stem}_record_read.bin`；
  不可覆蓋原檔：`請另存新檔，不要覆蓋原廠韌體（復原時需要它）。`
- 原廠工具：把韌體路徑複製到剪貼簿，於其資料夾啟動 exe；附加 `已啟動 IAP 工具；韌體路徑已複製到剪貼簿。` 或 `無法啟動 IAP 工具。`
- 關閉時，主視窗儲存 `iap_path`（非預設時）。

## 4. 狀態（2026-10-10）

全部里程碑都已完成（打包與自我檢查見 `rust/README.md`「打包與自我檢查」）。工具列與問題清單用 Python 版的線條圖示；

比對與測試：
- `tests/parity_table.json`（`tools/make_parity_gui.py`）：三個表格每一格的文字、排序值、編輯值、頻段問題，下拉選項，篩選與排序結果，
  約 60 個儲存格編輯，以及列印報告的 HTML（逐位元組相同）。
- `tests/parity_pages.json`（`tools/make_parity_pages.py`）：掃描清單、接收群組、對講機設定、常用短信、報警與加密頁的文字、選項、
  啟用狀態、成員編輯器初始狀態，以及 41 個經 `list_ops.py` 的編輯。
- egui_kittest 無視窗測試：各頁、表格雙擊編輯、讀寫頻（模擬對講機）、RadioID、備份管理、韌體升級、錄音；全部用暫存資料夾，不開實體序列埠。

與 Python 版刻意不同之處：
- 對話框是非模式視窗：開著時專案仍可能改變，所以 RadioID 會重讀既有 ID、成員編輯器在專案改變時關閉、韌體與錄音對話框跟著工具列的連接埠；
  「同時只能有一個傳輸」改為每幀檢查（主視窗讀寫頻、韌體升級、錄音下載互相阻擋）。關閉 RadioID 會取消下載。
- 列印、預覽列印用系統瀏覽器開啟 HTML 報告（A4 橫式、表頭每頁重複）；匯出 PDF 用無頭 Edge／Chrome，找不到時提示改用預覽列印另存。
- 報警名稱與加密金鑰是常駐的文字框（Enter 或離開時套用），不是雙擊表格儲存格；常用短信雙擊編輯，但打字或 F2 不會開始編輯。
- 數值框只有實際改變時才寫入；對講機設定的 `未知值 {raw}` 只在目前值未知時列出。
- 模擬對講機在多次傳輸間保留寫入的內容（Python 版每次都是新的模擬器，除非測試注入）。
- Python 會丟出例外或沒有訊息的地方改為中文訊息：分區表指到不存在的頻道（`（不存在）`）、播放器開不了、RadioID 的 I/O 與 CSV 錯誤、
  讀不到備份資料夾等；由作業系統產生的錯誤說明用字不同。
- `iap_path` 等於預設值時存成空字串。

## 5. 里程碑

1. ✓ 外框：字型、主題、設定與搬移、選單、開啟／儲存、最近開啟、拖放、標題、關閉確認、編碼、問題清單、裝置資訊、復原／重做。
2. ✓ 表格：顯示格式（含 Python 比對答案）、頻道／分區／聯絡人表格、排序、搜尋與篩選、筆數、頻段外標紅。
3. ✓ 編輯與列操作：儲存格編輯器、所有頻道／分區／聯絡人操作（確認文字與復原標籤相同）、批次新增、清除換行。
4. ✓ 設定區頁面：別名與 DMR ID（含 RadioID 查詢）、掃描清單、接收群組、對講機設定、常用短信、報警與加密。
5. ✓ 匯入匯出與工具：頻道／聯絡人 CSV、RadioID 匯入（背景下載）、比較專案、關於。
6. ✓ 讀寫頻：流程在 `opendrs_core::radio_session`；連接埠＋模擬器、背景執行緒、進度、傳輸中停用與禁止關閉、寫入安全步驟、備份管理。
7. ✓ 韌體升級與錄音：安全條件、錄音讀取修補、原廠工具、停止、系統播放器。發佈前需實機驗證。
8. ✓ 列印／PDF、打包（`cargo xtask dist`）、自我檢查（`--self-test`）、視窗與執行檔圖示、工具列圖示。
