# OpenDRS

[![build](https://github.com/windasd/OpenDRS/actions/workflows/build.yml/badge.svg)](https://github.com/windasd/OpenDRS/actions/workflows/build.yml)

Kydera DR-8500UV／HORA DH-98VU 對講機的寫頻軟體，取代原廠 `DRS_V8.1-CH.exe`（Kydera，VB6）的 `.F136` 專案編輯器。
（舊名「DRS CPS（重寫版）」，2026-10-09 改名。）

**支援機型**：Kydera DR-8500UV／DRS-8500、**HORA DH-98VU**（DR-8500UV 的貼牌機）。三者是同一硬體平台（C7000），
對講機寫頻時一律回報機型 `DRS-8500`、型號 `DR8600`，所以本程式把它們視為同一機型；裝置資訊頁會在機型旁註明
這些名稱。讀寫頻、IAP 韌體升級與錄音讀取都是在一台 HORA DH-98VU（BK4819 射頻晶片）上實機驗證。

作者：windasd　版本：0.2.0　網站：https://github.com/windasd/OpenDRS（版本與執行環境見「工具 › 關於本軟體…」，可一鍵複製給問題回報使用）

| | 舊版 | 本版 |
|---|---|---|
| 語言 / 框架 | Visual Basic 6 / MSVBVM60 | Python 3.11+ / PySide6（Qt 6） |
| 名稱編碼 | 依 Windows 地區設定（ANSI），換電腦就亂碼或變 `?` | 明確選擇 Big5 / GBK / ASCII，開檔時自動偵測 |
| 無法表示的字 | 靜默變成 `?` | 拒絕寫入並說明是哪個字 |
| 無法解碼的名稱 | 亂碼 | 以 `‹十六進位›` 顯示，原始位元組原樣保留 |
| 設定檔 | `Program Files\DRS\Type.ini`（被 VirtualStore 分裂成兩份，ANSI） | `%APPDATA%\OpenDRS\settings.json`（UTF-8） |
| 存檔 | 直接覆寫 | 原子寫入 + 首次保留 `.bak` |

## 執行

**一般使用**：到 [Releases](https://github.com/windasd/OpenDRS/releases) 下載 `OpenDRS-<版本>-win64.zip`，解壓縮後執行 `OpenDRS\OpenDRS.exe`
（不需安裝 Python）。可把 `.F136` 拖到 exe 上開啟。

- 程式沒有數位簽章，第一次執行時 Windows 可能顯示「Windows 已保護您的電腦」：按「其他資訊」→「仍要執行」。
  可用 zip 旁的 `.sha256` 核對下載的檔案。
- 設定、備份、錄音放在 `%APPDATA%\OpenDRS\`；exe 版的執行記錄在 `%APPDATA%\OpenDRS\logs\opendrs.log`（回報問題時附上）。
  從改名前的版本升級：第一次啟動時會自動把舊資料夾 `%APPDATA%\DRSCPS\` 整個搬到 `%APPDATA%\OpenDRS\`（設定、備份、錄音、RadioID 資料），設定裡指向舊資料夾的路徑也一併更新；舊程式若還開著、無法搬移，就改為複製並保留舊資料夾。
- 寫頻線需要另外安裝驅動程式（例如 PL2303）。錄音轉 WAV 需要原廠的 `ambep2.exe`（授權軟體，不隨附）。

**從原始碼執行**：

```
run.bat                       （或）  run.bat 路徑\專案.F136
```

開發 / 測試：

```
.venv\Scripts\python -m pip install -e ".[dev,build]"
.venv\Scripts\python -m pytest --cov
```

## 打包與發佈

```
.venv\Scripts\python packaging\build.py
```

`packaging/build.py` 依序：產生 exe 圖示與版本資訊（檔案內容 › 詳細資料）→ 以 PyInstaller（`packaging/opendrs.spec`，
資料夾模式、無主控台視窗）打包 → 確認必要的 Qt 外掛與翻譯檔都在 → 以 offscreen 與實際 Windows 兩種平台外掛各執行一次
`OpenDRS.exe --self-test`（Qt、繁中翻譯、PDF、列印、SVG 圖示、TLS、序列埠列舉、Big5/GBK 全部要通過）→
放入第三方授權（`licenses\`，見 `packaging/licenses/THIRD_PARTY_NOTICES.md`）→ 壓縮成 `dist\OpenDRS-<版本>-win64.zip` 與 `.sha256`。
spec 會排除 widgets 程式用不到的 Qt 部分（Quick/QML、虛擬鍵盤、Qt Network、軟體 OpenGL 等），
解壓後約 63 MB、zip 約 27 MB。原始碼也可執行 `python -m opendrs --self-test 報告.json` 檢查環境。

**GitHub Actions**（`.github/workflows/build.yml`，在 `windows-latest` 執行）：

- 推送到 `main` 與每個 Pull Request：安裝（版本固定於 `packaging/requirements-ci.txt`）→ 語法／未定義名稱檢查 →
  全部測試 → 打包與自我測試；
  zip 以 Artifact（`OpenDRS-windows`，保留 30 天）提供下載。需要原廠韌體或 `ambep2.exe` 的測試在 CI 上自動略過。
- **發佈新版**：先把 `src/opendrs/__init__.py` 與 `pyproject.toml` 的版本改成新版本、在 `CHANGELOG.md` 寫好
  `## v<版本>（日期）` 一節並推送，再推送同名標籤：

  ```
  git tag v0.3.0
  git push origin v0.3.0
  ```

  標籤與程式版本不符、`CHANGELOG.md` 沒有這一版的紀錄、或標籤指向的 commit 不在 `main` 上時不會發佈；
  通過後自動建立 GitHub Release，附上 zip 與 `.sha256`，說明文字就是 `CHANGELOG.md` 的那一節
  （程式的「檢查更新」也顯示它；標籤以 `a1`、`b1`、`rc1` 結尾時標為預先發行版）。
- 所有 Actions 都固定在 commit SHA，Python 套件固定在 `packaging/requirements-ci.txt`；`.github/dependabot.yml`
  每週檢查兩者的新版並開 PR，PR 經過 CI 測試與打包後再合併。發佈用的建置不使用 pip 快取。
- 只有發佈 Release 的工作有寫入權限，而且它不執行任何建置工具，只上傳已建好的檔案。
- 建議在 GitHub 的 Settings › Rules › Rulesets 為 `v*` 標籤加規則，只允許維護者建立，避免他人推送標籤觸發發佈。

## 功能

- **外觀**：淺色／深色主題（檢視 › 外觀，預設跟隨 Windows 設定並記住選擇），工具列與選單附圖示，
  裝置資訊以卡片分組，問題清單顯示數量；名稱編碼選單在視窗右下角狀態列。

- 開啟、編輯、儲存 `.F136` 專案與舊版 `backup.ini`（同格式）。
- 頻道：名稱、接收／發射頻率、**發話對象**（下拉選聯絡人，可打字搜尋；記錄 +0x1E 為聯絡人編號，
  以 3 份實際專案的 TG 頻道 ↔ TG 聯絡人逐一比對確認），並顯示所屬**分區**；分區：名稱；聯絡人：名稱、呼叫 ID。
- **頁面按鈕**：頻道、分區、聯絡人分頁的表格上方有「新增」「刪除」「上移」「下移」等按鈕（頻道另有「批次新增」、
  聯絡人另有「RadioID 匯入」），與選單的同名項目相同；掃描清單、接收群組分頁的「新增清單…」編輯第一個未使用的清單。
- **新增頻道**（頻道分頁的「新增」，或頻道／分區 › 新增頻道）：複製選取的頻道，加在同一分區最後面，之後的分區自動順延、
  計數同步。掃描清單以「分區＋區內序號」引用頻道，加在分區尾端不會改變任何既有引用。
- **刪除頻道**（頻道／分區 › 刪除頻道，或在頻道表按 Delete）：同分區之後的頻道編號往前補、之後的分區順延，
  並改寫掃描清單——指向被刪頻道的項目移除（後面的往前移），同分區較大的序號減一，
  確認對話框會列出受影響的筆數。分區的最後一個頻道不能刪。
  掃描清單格式已由韌體確認（設定區 0x12B 起 16 組 × 0x50 bytes：名稱 10 bytes、設定 6 bytes、
  16 筆〔分區, 區內序號〕）；韌體開機時只會丟掉指向不存在頻道的項目，若不改寫，
  中間刪除後的項目會默默指到「下一台」頻道，因此必須由本程式重新編號。
- **排序**：頻道（同分區內）與聯絡人可上移／下移（Ctrl+↑／Ctrl+↓ 或選單）。對調的兩筆在掃描清單、
  GPS／報警信道、發話對象、接收群組中的引用一併對調，仍指向同一台頻道／同一個聯絡人。
- **批次新增頻道**（頻道／分區 › 批次新增頻道…，同舊軟體 ADD++）：以選取的頻道為範本，一次加 1–64 台到
  同分區最後，設定起始接收頻率、間隔（kHz）、發射差頻、名稱前綴與起始編號；超出頻段時不能確定。
- **換分區**：頻道表的「分區」欄是下拉選單，選另一個分區即把頻道移到該分區最後一台；
  原分區後面的頻道往前遞補，掃描清單、GPS上報信道、報警信道中指向它的項目跟著改成新位置。
  分區的最後一個頻道不能移走。
- **新增／刪除分區**（頻道／分區選單）：新增分區加在最後，第一台頻道複製目前選取的頻道；
  刪除分區連同其中頻道一併移除，之後的分區往前遞補，掃描清單中指向該分區的項目移除、
  之後分區的編號自動減一。至少保留一個分區。
- **掃描清單分頁**：列出 16 個清單位置的名稱與成員；雙擊或「編輯選取的清單…」可改名、
  勾選最多 16 台頻道（依頻道清單順序掃描；每組 6 bytes 的掃描設定原樣保留）。
- 發話對象指向不存在的聯絡人時列入問題清單並禁止存檔。
- **模式／色碼／時槽**：頻道模式（類比、數位、類比+數位〔發射類比〕、類比+數位〔發射數位〕）
  與時槽以下拉選單、色碼（0–15）直接輸入。依據韌體頻道解析程式 FUN_030315a8
  （+0x14 bits 7–6、+0x15 bits 0–3 與 bit 5）及舊軟體語系檔的選項名稱；只改對應的 bits。
- **接收群組**：頻道的「接收群組」欄（+0x17，0 = 無）可下拉選擇；「接收群組」分頁列出 32 個
  群組位置，雙擊可改名並勾選最多 32 個聯絡人（可篩選）。格式由韌體 FUN_03031284 確認：
  設定區 0x62B 起（緊接掃描清單之後）每組 0x4C bytes，名稱 10 bytes ＋ u16 聯絡人編號。
- **新增聯絡人**（聯絡人分頁的「新增」，或聯絡人 › 新增聯絡人…）：輸入類型（組呼、個呼、全呼、無地址呼）、
  名稱與 ID，加在清單最後面，其他聯絡人的編號不變；類型預設與選取的聯絡人相同。相同類型與 ID 的聯絡人已存在、
  名稱超過 10 bytes 或已達 1000 筆上限時，對話框會說明原因、不會新增。
- **刪除聯絡人**（聯絡人 › 刪除選取的聯絡人，或在聯絡人表按 Delete，可多選）：之後的聯絡人編號往前
  遞補，頻道發話對象與接收群組成員自動改成新編號，被刪的群組成員一併移除。仍被頻道當成
  發話對象的聯絡人不能刪（會列出是哪些頻道）。韌體中讀取聯絡人的只有發話對象、接收群組與
  「本頻道聯絡人」顯示畫面三處，因此這兩種引用就是全部。
- 裝置資訊頁顯示機型、頻段、寫入時間、別名與**本機 DMR ID**（設定區 +0x90，3 bytes）；已下載 RadioID 資料時
  一併顯示登記的呼號、名字、城市，別名與登記呼號不同時提示（呼號可能已變更），並可一鍵「以 RadioID 呼號更新別名」。
  別名（最多 15 個 ASCII 字元）與 DMR ID（1–16776415）可直接修改，按 Enter 或離開欄位即套用、可復原；
  只改這兩個欄位的位元組（DMR ID 後一 byte 屬其他設定，保持不變），存檔或寫入對講機後生效。
  （2026-10-08 實機驗證：別名 QA0AFK → QA0AJS 寫入後讀回一致，只有別名與寫入時間的位元組改變。）
- 依專案內的頻段標示（如 `F136-480` = 136–174 及 400–480 MHz）檢查頻率，超出者標紅且禁止存檔。
- 未修改的專案存回時與原檔 **逐位元組相同**（3 份實際專案檔已驗證）。
- 程式不認得的欄位與整個設定區一律原樣保留。

### 從 RadioID.net 匯入聯絡人

工具列「從 RadioID 匯入聯絡人…」。首次使用會下載 radioid.net 的 `user.csv`（約 17 MB，
31 萬筆），快取於 `%APPDATA%\OpenDRS\radioid\`；之後離線篩選，按「下載／更新資料」才會
重新下載（帶 `If-Modified-Since`，沒變就不重抓）。

- **地區**：下拉選國家（預設 Taiwan，711 筆），括號內為筆數。
- **ID 前綴**：例如 `466` 只列台灣 ID。
- **搜尋**：比對 ID、呼號、姓名、城市，多個關鍵字以空白分隔（全部符合才列出）。
- 勾選要匯入的人，或「全選符合結果」；已在聯絡人中的 ID 以灰色「已存在」標示，勾選後不會重複新增：原名稱看起來是呼號（包含已變更的舊呼號），或與 RadioID 的呼號／名字相符時，換成新名稱（編號、類型、ID 不變）；自訂名稱（如「老王」「台中中繼」）則保留原名稱。
- **名稱格式**：呼號／呼號 名字／名字。名稱欄只有 10 bytes，超過的會在字元邊界截短
  （中文字不會被切半），重音字母轉為一般字母（José → Jose），匯入後列出被截短的筆數。
- 匯入為個呼（類型 5），索引接續現有最後一筆；容量上限 **1000**（對講機韌體會把超過 1000 筆
  視為損壞而整段清空；舊軟體說明文件寫的 2000 是錯的），超過部分不匯入並提示。
- 下載內容視為不信任資料：限制大小、檢查標頭後才取代快取、嚴格 UTF-8、逐列驗證 ID。

舊軟體匯入的聯絡人名稱常夾帶換行字元（實際專案 359 筆中 343 筆），本程式以 `␍␊`
顯示出來，問題清單也會提示。按工具列「清除名稱中的換行字元」可一次清除（聯絡人、分區、頻道名稱都會檢查）：只改名稱字串本身，結束標記之後的位元組與其他欄位一律不動；夾在中間的換行換成空格。清除後要存檔才生效，首次存檔保留的 `.bak` 即為清除前的原檔。新匯入的名稱不會有這個問題。

### 編輯輔助

- **復原／重做**（Ctrl+Z／Ctrl+Y）：儲存格編輯、RadioID 匯入、CSV 匯入、清除換行字元都可退回；
  功能表會顯示下一步要復原的是什麼。
- **搜尋**（Ctrl+F）：頻道、分區、聯絡人分頁上方各有搜尋框；多個關鍵字以空白分隔（全部符合才列出），
  「範圍」可限定只搜名稱、ID 等單一欄位；分頁標題顯示總筆數，右側顯示「顯示 N / M 筆」。
- **過濾**：聯絡人可只看某一類型（組呼／個呼／全呼／無地址呼）；「顯示」可只列名稱含換行字元、
  名稱重複，或（聯絡人）類型與 ID 重複的資料。
- **排序**：點欄位標題排序（ID、編號、頻率依數值，名稱不分大小寫），再點一次反向，第三次回到原順序；
  「清除篩選與排序」一鍵還原。排序只影響顯示，存檔／寫入對講機的順序與編號不變。
- **最近開啟**（檔案 › 最近開啟）與**拖放開檔**。

### 聯絡人 CSV

- 匯出：UTF-8 帶 BOM、CRLF，Excel 直接開不亂碼。欄位 `No,CallType,Name,ID`。
- 匯入：接受 UTF-8（有無 BOM）與舊的 Big5／GBK 檔；表頭可用英文或中文
  （名稱／名称、ID／號碼／号码、類型）；類型可寫 4–7 或組呼／個呼／全呼／無地址呼，
  省略時當作個呼。無法使用的列會逐列列出原因，其餘照常匯入。
- 新聯絡人附加在最後；相同類型且相同 ID 已存在者以 CSV 的名稱覆蓋（編號不變），不會重複新增。

### 頻道 CSV（頻道／分區 › 匯出頻道 CSV／從 CSV 匯入頻道）

- 匯出：每個頻道一列、依分區排列，UTF-8 帶 BOM、CRLF，Excel 直接開。欄位與頻道表相同
  （分區、分區名稱、頻道、名稱、收發頻率、模式、色碼、時隙、功率、亞音……）；
  發話對象、接收群組、加密、掃描、緊急系統寫成「編號 名稱」。
- 匯入只更新與新增，**不會刪除頻道**：
  - 以「分區＋頻道（分區內第幾個）」找到要更新的頻道；只套用檔案裡有的欄位，空白儲存格保留原值。
  - 「頻道」欄空白或超過該分區的頻道數 → 在該分區最後新增一個（以該分區最後一個頻道為底，需有名稱）。
  - 參照欄位可寫編號、「編號 名稱」（兩者不符會被拒絕）或完整名稱；表頭可用中文或英文（Zone、Ch、Name、RX (MHz)…），
    逗號、分號或 Tab 分隔皆可。
  - 任何一格有問題（例如頻率超出本機頻段、參照不存在）就整列略過並列出原因，不會留下改一半的頻道。
  - 「分區名稱」與該編號的分區不符時略過該列（避免分區順序改變後套到錯的分區）；同一頻道在檔案中只能出現一次；
    要新增的頻道若該分區已有相同名稱與頻率者則略過，所以同一個檔案重複匯入不會重複新增。
- 套用前會顯示「更新／新增／未變動」數量確認，整次匯入是一個復原步驟。

### 列印與 PDF（檔案 › 列印…／預覽列印…／匯出 PDF…）

- 內容：裝置資訊、每個分區的頻道表（頻率、模式、色碼、時隙、功率、發話對象、接收群組、掃描列表、亞音）、
  聯絡人、接收群組成員、掃描清單成員與發射模式。A4 橫式，表頭在每一頁重複。
- 「匯出 PDF」不經過印表機驅動程式，沒有安裝印表機也能用；預設檔名與專案相同（`.pdf`）。

### 韌體升級（對講機 › 韌體升級（IAP））

兩種方式，都先經過同一套事前檢查：

- **內建升級**：透過工具列選的寫頻線直接與對講機的 IAP bootloader 通訊（`iap.py`）。協定由原廠
  `IAP+Flash.exe` 逆向而來，並讓原廠工具本身對著模擬 bootloader 跑完整升級（以 Frida 攔截它的串口
  API，不接任何硬體）逐位元組比對：原廠韌體與兩個合成檔，我們送出的資料與原廠工具**完全相同**。
  2026-10-09 已在實機（DR-8500UV，BK4819）以內建升級成功刷入原廠韌體與錄音讀取修補版各一次。
  開始前須勾選「已進入升級模式」；檔案檢查有警告時另須勾選「我了解風險」。
  工具列選「模擬對講機」時接的是模擬 bootloader，可安全演練整個流程。
- **原廠工具**：啟動原廠 `IAP+Flash.exe`（預設 `C:\Program Files (x86)\IAP(APP+FLASH)\`，可另選並記住），
  韌體檔路徑已複製到剪貼簿。

協定（PC → 對講機）：`"Erase      "` + 位址 u32 BE（原廠工具預設 0）+ 最後一頁索引 u32 BE（= 檔案大小 // 2048）
→ 對講機回覆含 `ok` 的文字 → 逐頁送 2048 bytes（最後一頁補 0x00；索引含最後一頁，所以大小剛好是 2048
倍數時會多送一整頁 0，與原廠工具相同）→ 每頁回 `kyd` → 最後回 `ChecksumI` + 全部頁面位元組總和 u32 BE。
清除後到全部寫完之前對講機沒有可用的韌體；中途失敗時對講機停在升級模式，重新執行升級即可。

檢查項目：

- 從韌體檔中取出韌體 ID 與編譯日期，與對講機上次讀取回報的版本比對：相同 → 通過；同一硬體（如 308E）但
  版本不同 → 警告，須勾選「我了解風險」才能啟動；不同硬體或找不到 ID → 禁止。
- 檔案內的韌體 ID 是樣板（`308E.B6.TARSCB.003`）：韌體開機時讀取射頻晶片 ID，改寫 `308E.B` 後面兩個字元
  （BK4819 → `BK`、RDA1846／AT1846S → `Ax`、0x6818 → `6.` 不變、0x7813 → `64`）。所以對講機回報的
  `308E.BBKTARSCB.003` 與原廠檔 `308E.B6.TARSCB.003` 是同一版本，比對時視為相同 → 通過。
- 已知的原廠檔以 SHA-256 辨識：`C7000_DR8500UV_4819_03_136174_400480.bin`（136-174／400-480）與
  `C7000_DR8500UV_4819_05_144146_430440.bin`（144-146／430-440 業餘頻段版；程式與 03 版完全相同，只差頻段限制常數與
  編譯日期 Mar 16 2024）；分析過程產生的只改頻段版韌體（頻段限制被放寬，
  超出原廠頻段的射頻表現未經驗證）一律禁止。
- 錄音讀取修補版（`DR8500UV_B6_record_read.bin`，原廠檔改 30 bytes，讓對講機回應電腦讀取錄音的指令）以 SHA-256
  辨識 → 警告（需勾選確認）：已在實機驗證錄音讀取；對講機是同一版本時，再刷一次原廠檔即可復原。
- 改頻段測試版加錄音讀取修補（`DR8500UV_136-180_400-520_relabelled_record.bin`，`mkpatch_band_record.py` 產生，
  原廠檔改 76 bytes；2026-10-11 已實機刷入，旋鈕可調到 5XX MHz，但 VFO 鍵盤只接受 1、4 開頭）與再加鍵盤修正的版本
  （`…_record_keypad.bin`，`mkpatch_keypad.py` 產生，再改 32 bytes，讓鍵盤首位也接受 5；同日實機確認鍵盤可輸入
  5XX MHz）以 SHA-256 辨識 → 警告
  （需勾選確認），並說明超出原廠頻段的部分沒有出廠校準、未經驗證。
  刷入後對講機回報頻段 `F136-520`，本程式據此允許 136–180／400–520 MHz 的頻道頻率；請先重新「讀取對講機」，
  頻段標示仍為 136-480 的舊專案不能寫入這台對講機。刷回原廠檔後反過來也一樣：要重新讀取，且 174–180／480–520 MHz
  的頻道仍留在對講機設定裡，原廠韌體不會使用它們，請改掉或刪除。
- 今天是否已有從對講機讀取的備份；本程式正在讀寫時禁止啟動（避免搶 COM 埠）。

**產生錄音讀取版**：選好原廠檔後按「產生錄音讀取版…」，程式把原廠檔改 30 bytes（`fwpatch.py`，與實機驗證過的
`DR8500UV_B6_record_read.bin` 相同的修補；03 與 05 版都適用）另存新檔並改選它，原廠檔不會被修改。每個修補點都先
核對原始位元組；不是已知原廠檔時另外掃描全圖，確認沒有其他程式會進入被覆寫的區域。要復原時再刷一次原廠檔。

用原廠工具時，在 IAP 工具按「Open APP File」貼上路徑即可；任何一種方式升級中都不可拔線或關機。

### 讀取錄音（對講機 › 讀取錄音）

取代原廠 `C:\wav\Wav.exe`：列出對講機的通話錄音、勾選下載，轉成 WAV。

- 「讀取清單」：最多讀幾筆可調（預設 100，與原廠相同），表格列出編號、收／發、對方 ID、聯絡人、長度（秒）、時間。
  時間來自對講機的時鐘；若日期不對，用「對講機 › 校正對講機時鐘…」校正後，之後的錄音就會正確。
  聯絡人優先用專案聯絡人的名稱；不在聯絡人裡的 ID，若已下載 RadioID 資料（聯絡人 › 從 RadioID 匯入聯絡人）
  就顯示登記的「呼號 姓名」（離線查詢，每個 ID 只查一次；群組 ID 查不到時留白）。
- 點欄位標題可排序（編號、對方 ID、長度依數值），排序後勾選與下載不受影響；「全選」「全不選」一次切換勾選；
  表格下方顯示「共 N 筆，合計 X 分 Y 秒」，下載完成的訊息也附上這次下載的總長度。
- 「下載勾選的錄音」：每筆存 `<日期>_<時間>_<編號>_<R|S><ID 8 位>.ambe`（對講機原始 AMBE+2 資料，例如
  `20250607_1234_1_R09998765.ambe`）與 `.wav`，預設放在 `%APPDATA%\OpenDRS\recordings`（可改）；
  雙擊或按「播放」以系統預設程式播放。
- 「依編號全部下載」：不讀清單，直接從第 1 筆讀到最後一筆，給不支援清單指令的韌體用。
- 解碼用原廠附的 DVSI `ambep2.exe`（預設 `C:\wav\ambep2.exe`，可另選並記住）；它是授權軟體，本程式只呼叫、
  不附帶也不重寫。找不到時仍會保存 `.ambe` 原始資料。PCM → WAV 由本程式自己寫，不需要 ffmpeg。
- 協定與原廠 Wav.exe 送出的位元組相同（測試以擷取到的 Wav.exe 輸出比對）；細節見 `recording.py` 與
  `legacy_probe/wav_harness/README.md`。原廠 Wav.exe 超過 9 秒的錄音會轉壞（寫檔位置算錯），本程式沒有這個問題。
- **原廠韌體不支援，需刷入錄音讀取修補版**：原廠韌體（308E.BBKTARSCB.003＝原廠檔 B6. 在 BK4819 硬體上的版本字串）
  的接收迴圈沒有接上這兩個指令，實測完全沒有回應，原廠 Wav.exe 同樣讀不到。`mkpatch_record.py` 產生的
  `DR8500UV_B6_record_read.bin`（原廠檔改 30 bytes）把韌體內現成的錄音讀取程式接上；2026-10-09 以 IAP 刷入後實測
  讀取清單並下載 25 筆錄音（含多塊、最長 37 秒）正常。要還原時再刷一次原廠檔即可。

### 檢查更新（工具 › 檢查更新…）

- 查詢 GitHub 上[最新發佈的版本](https://github.com/windasd/OpenDRS/releases)，顯示版本號與更新說明。
- **exe 版可直接「下載並安裝」**：下載 `OpenDRS-<版本>-win64.zip`，用 GitHub 回報的 SHA-256 與發佈附的 `.sha256` 檔
  兩者核對（任一不符就不安裝），解壓到程式資料夾旁的暫存資料夾，再關閉程式（有未儲存的修改會先詢問）。
  接著由 PowerShell 小程式等程式結束後替換 `OpenDRS.exe`、`_internal`、`licenses`、`README.md`，並自動重新開啟。
  - 只替換這四項：放在同一資料夾的其他檔案不會動；設定、備份、錄音在 `%APPDATA%\OpenDRS\`，不受影響。
  - 替換失敗（例如檔案被占用）會還原舊版，紀錄在 `%APPDATA%\OpenDRS\logs\update.log`。
  - 程式所在資料夾沒有寫入權限（例如放在 `Program Files`）時，請到發佈頁面手動下載。
- 從原始碼執行時只提示有新版本，請用 `git pull` 更新。
- **啟動時自動檢查**（預設開啟，可在對話框取消）：每天最多一次，在背景向 `api.github.com` 查詢；有新版本時只在
  狀態列與選單提示，不會自動下載。
- 校驗碼與 zip 來自同一個發佈，能擋下載不完整或損壞的檔案，但不能防止 GitHub 帳號被盜用後發佈的惡意版本
  （程式沒有數位簽章）。

### 比較專案（工具 › 比較專案）

把目前專案與另一個專案逐位元組比較：裝置資訊、聯絡人／分區／頻道逐列（頻率以 MHz 顯示）、
設定區的每一處差異（偏移、前後十六進位與 ASCII），可存成 UTF-8 文字報告。
主要用途是找出未知設定的存放位置：在舊軟體只改一個設定、另存，再用這裡比較。
記錄是依「第幾列」比對，所以順序有調動時會顯示為多列變更。

### 對講機讀寫（對講機選單）

經寫頻線（115200 bps，8N1）直接讀寫對講機。協定由 2026-10-08 舊軟體實際讀寫的 USB 擷取
解出，並以韌體的傳輸處理程式交叉驗證；`tests/fixtures/capture/` 保存了那次擷取，測試會重播它，
確認本程式送出的每個位元組都與舊軟體相同。

- 工具列「連接埠」下拉選單選寫頻線（「重新整理」可在插拔後重新列出；會記住上次使用的埠），
  按「讀取對講機」／「寫入對講機」即開始，不另開視窗：進度顯示在視窗右下角狀態列，
  傳輸期間編輯區與讀寫按鈕暫停使用，傳輸中無法關閉程式。
- **讀取**：讀完自動在 `%APPDATA%\OpenDRS\backups\` 保留 `.F136` 與原始 `.bin` 備份，內容載入視窗（尚未存檔）。
- **寫入**：確認對話框列出目標連接埠與分區／頻道／聯絡人數量，按「是」後：
  1. 先讀取對講機目前的設定並備份（同時確認連線正常）；
  2. 比對對講機回報的機型與頻段和專案是否相同，不符就在送出任何資料前中止；
  3. 依韌體公式計算區塊數後寫入，逐塊等待確認；
  4. 核對對講機回報的校驗和。
- 對講機會先把資料存到暫存區，全部收完才套用，中途斷線不會破壞原本的設定。
  但校驗和是在套用之後才回報；若真的不符，請用上一步的備份寫回。
- 寫入時間以固定格式 `YYYY/MM/DD HH:MM` 記錄。**對講機在寫入完成時依這個時間設定時鐘**（韌體 `FUN_03027aec`，
  精確到分鐘、秒數不變），所以每次寫入都會順便校正時鐘。韌體只接受「年在前」的格式；舊軟體在英文（美國）
  地區設定的電腦上寫出 `10/8/2026 16:54` 這種日期，對講機不採用，時鐘不會被設定。
- **校正對講機時鐘（對講機 › 校正對講機時鐘…）**：不改任何設定、只校正時鐘。先讀取並備份，再把讀到的資料
  原樣寫回、只更新寫入時間；寫回前確認資料能逐位元組重建，否則中止、不寫入。目前編輯中的專案不受影響。
  寫入完成後對講機會重新啟動，可在對講機選單的「日期／時間」確認。
- 連接埠清單最後有「模擬對講機」，不接實機也能試用整個流程。

### 備份管理（對講機 › 備份管理…）

每次讀取對講機、以及每次寫入之前，都會在 `%APPDATA%\OpenDRS\backups\` 留下一份備份：
`<日期>_<時間>_<read|before_write>_<機型>.F136`（專案）與同名的 `.bin`（原始傳輸資料）。這裡可以瀏覽它們：

- 清單由新到舊，列出時間、類型（讀取／寫入前）、機型、分區／頻道／聯絡人數量與大小（.F136＋.bin）；
  「備註」欄標出最近一次寫入前的備份，讀不出來的備份則顯示「無法讀取」與原因。
  開啟對話框時逐一讀取每份備份（每份數毫秒，100 份約 0.5 秒）。
- **開啟**（或雙擊）：載入為目前的專案，有未儲存的修改時先詢問。開啟的備份不會被覆寫——存檔時一律另存新檔，
  也不會加入「最近開啟」。要把備份寫回對講機：開啟後按「寫入對講機」。
- **與目前專案比較**：用「比較專案」的報告列出目前專案與這份備份的差異。
- **開啟資料夾**、**刪除…**（確認後刪除這份備份的 `.F136` 與 `.bin`，不會動到資料夾裡的其他檔案）。
- **只保留最近 N 份 › 清理…**：確認後刪除較舊的備份；最近一次「寫入前」的備份即使較舊也一律保留
  （寫入後出問題時就是用它寫回）。只處理符合上述檔名格式的檔案。

## 已知限制（重要）

尚待在實機確認的項目與步驟見 [`實機測試清單.md`](實機測試清單.md)。

1. 讀寫頻只以一台 HORA DH-98VU（回報 DRS-8500、`F136-480`，韌體 `308E.BBKTARSCB.003`）的擷取驗證過。
   其他機型或韌體版本未測試；機型／頻段不符時本程式會拒絕寫入。
2. 讀寫頻密碼一律送空白（與擷取中的舊軟體相同）。韌體分析顯示這版韌體的密碼檢查不會被執行（設定存取器沒有
   密碼欄位的分支，檢查恆為通過），所以對講機即使在舊軟體設過密碼也能讀寫；本程式因此不提供密碼輸入。
3. 聯絡人可刪除、上下移動（頻道發話對象與接收群組跟著調整）；預設按鍵（PTT 1–3）若綁定聯絡人，其儲存方式尚未確認
   （韌體中未見以編號讀取），刪除或移動後請在對講機上確認。
4. 新增／刪除頻道、分區與掃描清單編輯已通過離線測試（重新載入、組成寫入資料流），尚未在實機寫入驗證；每個分區／全部頻道的
   數量上限尚未確認。對講機若另外記住「目前所在頻道」，刪除後可能停在相鄰頻道。
5. 只編輯已確認意義的欄位；其他頻道屬性、掃描列表、設定區內容以原始位元組顯示或保留，未提供編輯。
